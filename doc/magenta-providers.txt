ANTHROPIC                                                 *magenta-anthropic*

Uses the Anthropic Node SDK.
https://github.com/anthropics/anthropic-sdk-typescript

Supported models:~
  - claude-sonnet-5
  - claude-opus-4-8
  - claude-haiku-4-5

Basic configuration:~
>lua
    {
      name = "claude-sonnet-5",
      provider = "anthropic",
      model = "claude-sonnet-5",
      fastModel = "claude-haiku-4-5",
      thinkingModel = "claude-opus-4-8",
      apiKeyEnvVar = "ANTHROPIC_API_KEY",
      thinking = {
        enabled = true,
        effort = "medium"        -- recommended default
      }
    }
<

With thinking/reasoning:~

Sonnet 5 and Opus 4.7+ use adaptive thinking (no explicit budget needed):
>lua
    {
      name = "claude-opus",
      provider = "anthropic",
      model = "claude-opus-4-8",
      apiKeyEnvVar = "ANTHROPIC_API_KEY",
      thinking = {
        enabled = true,
        displayThinking = false,  -- set true to stream thinking summaries
        effort = "max"            -- "low" | "medium" | "high" | "xhigh" | "max"
      }
    }
<

Older models (Opus 4.6 and earlier) require explicit budget:
>lua
    {
      name = "claude-opus-old",
      provider = "anthropic",
      model = "claude-opus-4-6",
      apiKeyEnvVar = "ANTHROPIC_API_KEY",
      thinking = {
        enabled = true,
        budgetTokens = 1024  -- must be >= 1024
      }
    }
<

Configuration options:~
  - `enabled`: Enable thinking for extended processing
  - `budgetTokens`: (optional) Token budget for thinking. Required for
    models before Opus 4.7; Opus 4.7+ uses adaptive allocation
  - `displayThinking`: (optional, default false) Stream thinking summaries
    to chat. Set true to see the thinking process as it streams
  - `effort`: (optional) Steer how aggressively Claude thinks and spends
    tokens on tool calls. One of "low" | "medium" | "high" | "xhigh" | "max".
    Maps to Anthropic's `output_config.effort`. Applies only to
    adaptive-thinking models (Opus 4.7+, Sonnet 4.6+); ignored with a
    warning on older models. See
    https://platform.claude.com/docs/en/build-with-claude/effort

                                                         *magenta-claude-max*
CLAUDE MAX AUTHENTICATION ~

Use OAuth to connect with your Anthropic account subscription instead
of pay-per-token API usage.
>lua
    {
      name = "claude-max",
      provider = "anthropic",
      model = "claude-sonnet-5",
      authType = "max"
      -- No apiKeyEnvVar needed
    }
<

How it works:~
  - On first use, opens browser to Anthropic's OAuth page
  - Copy authorization code back to Magenta
  - Tokens stored in `~/.local/share/magenta/auth.json` (0600 permissions)
  - Refresh tokens managed automatically

                                                    *magenta-claude-keychain*
CLAUDE CODE KEYCHAIN AUTHENTICATION ~

On macOS, reuse the Anthropic Console API key that Claude Code stores in
the login Keychain (after authentication with the "Anthropic Console Account" / API-usage-billing
sign-in mode of Claude Code). Magenta will load the key from the Keychain
at startup; no environment variable is required.
>lua
    {
      name = "claude-keychain",
      provider = "anthropic",
      model = "claude-sonnet-5",
      authType = "keychain"
      -- No apiKeyEnvVar needed
    }
<

How it works:~
  - Runs `security find-generic-password -s "Claude Code" -a $USER -w`
    to read the `sk-ant-*` key Claude Code stored in the login Keychain
  - Requests include the Claude Code system-prompt shim, since some orgs
    restrict console-managed keys to Claude-Code-shaped traffic
    will fail without an API key

Requires: You must have signed into Claude Code using the "Anthropic
Console Account (API usage billing)" option at least once on this machine.

OPENAI                                                       *magenta-openai*

The OpenAI provider speaks the Responses API. With an API key:
>lua
    {
      name = "openai",
      provider = "openai",
      model = "gpt-5.4",
      apiKeyEnvVar = "OPENAI_API_KEY"
    }
<
                                                     *magenta-openai-chatgpt*
CHATGPT SUBSCRIPTION AUTHENTICATION ~

Instead of an API key you can use a ChatGPT Plus/Pro subscription. This is
an unofficial integration and is opt-in via `authType = "chatgpt"`:
>lua
    {
      name = "chatgpt",
      provider = "openai",
      model = "gpt-5.4",
      authType = "chatgpt"
      -- No apiKeyEnvVar needed
    }
<
How it works:~
  - Magenta does not run the OAuth flow itself. It reads the credentials
    the `codex` CLI writes to `$CODEX_HOME/auth.json` (default `~/.codex`),
    and refreshes them non-interactively as they near expiry.
  - Run `codex login` once first. If the CLI is not logged in, magenta will
    run `codex login` for you and stream its output as notifications.
  - Requests go to `https://chatgpt.com/backend-api/codex`.
  - The codex CLI must be configured to store credentials in a file, not
    the OS keyring (`cli_auth_credentials_store = "file"` in
    `$CODEX_HOME/config.toml`).

Model support is an entitlement matter and changes over time. Codex-family
models (`*-codex`) and plain `gpt-5` / `gpt-5.1` are rejected for
ChatGPT-account auth; as of Aug 2026 `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.5`,
`gpt-5.6-sol`, `gpt-5.6-terra` and `gpt-5.6-luna` work on a Plus plan. Set
both `model` and `fastModel` explicitly on the profile, since the default
`fastModel` may not be one the codex backend serves.

                                                     *magenta-openai-bedrock*
BEDROCK (MANTLE) AUTHENTICATION ~

OpenAI's frontier models are also served by Amazon Bedrock through its
`bedrock-mantle` endpoint, which speaks the Responses API. Opt in with
`authType = "bedrock"`:
>lua
    {
      name = "gpt-5.6-terra(bedrock)",
      provider = "openai",
      model = "openai.gpt-5.6-terra",
      fastModel = "openai.gpt-5.6-luna",
      authType = "bedrock",
      env = {
        AWS_PROFILE = "my-profile",
        AWS_REGION = "us-west-2"
      }
    }
<
How it works:~
  - Requests are signed with AWS SigV4 using the standard credential chain,
    so the credentials cached by `aws sso login` work directly and no
    Bedrock API key is needed.
  - `env.AWS_PROFILE` selects the profile; `env.AWS_REGION` defaults to
    `us-west-2`. Static `env.AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`
    (plus optional `AWS_SESSION_TOKEN`) are used instead when set.
  - `tokenRefreshCommand` works here just as it does for |magenta-bedrock|:
    when a request fails because the SSO session lapsed, the command is run
    and the request retried once. Note that credential failures surface from
    the OpenAI SDK as `Connection error.`; magenta appends the underlying
    cause to the message it reports.
  - The base URL defaults to
    `https://bedrock-mantle.<region>.api.aws/openai/v1`. Note the `openai/`
    prefix: the frontier models live on that path, while the openly-licensed
    models (`openai.gpt-oss-*`) are served from `/v1` instead. Override with
    `baseUrl` if you need the latter.
  - Model ids are Bedrock ids, e.g. `openai.gpt-5.4`, `openai.gpt-5.6-terra`.
  - The calling principal needs `bedrock-mantle:CreateInference`; the
    `bedrock:InvokeModel` permissions used by the |magenta-bedrock| provider
    are not sufficient, since mantle is a separate service namespace.
